## A 版 · 投「游戏客户端 / 前端 / 通用开发」

**三维资产库预览小程序** | 个人项目 | 2026.11
微信小程序 · XR-FRAME · GLB · 腾讯云 COS

- 基于微信 XR-FRAME 实现 3D 资产在线预览，支持手势旋转缩放、带参分享、本地文件导入，主包体积控制在 **83 KB**（上限 2 MB）
- 搭建 GLB 离线优化流水线（gltf-transform：网格精简 + 贴图降采样），模型体积 **3.60 MB → 1.18 MB（-67%）**
- **通过三组对照实验**定位 XR-FRAME 不支持 Draco / meshopt 几何压缩扩展，据此调整优化策略，避免上线后黑屏
- 解决真机环境三类兼容问题：小程序包体积超限、服务器域名校验、PC 端容器不支持 3D 渲染

## 面试大概率会问的问题（提前想好）

| 问题 | 回答要点 |
|---|---|
| **为什么不用 Three.js？** | 项目约束是微信原生，XR-FRAME 是官方方案，不占主包、不用维护适配层 |
| **Draco 那个实验怎么做的？** | 同一模型三份导出 → 上传 COS → 小程序逐个加载 → 只有无扩展版能渲染；再查 `gltf-transform inspect` 确认扩展依赖 |
| **-67% 是怎么压的？** | 主要是贴图降采样（2048→1024）+ 网格精简；几何压缩试过但 XR-FRAME 不支持 |
| **遇到过最难的 bug？** | 分享冷启动时 `xr-scene` 场景建不出来 —— 预览页作为启动页时渲染器未初始化，最终改为分享链接指向首页、由首页跳转解决 |
| **一个人做的吗？** | 是。AI 辅助生成代码，但每个技术决策和排查过程都是自己做的（这也诚实且加分） |

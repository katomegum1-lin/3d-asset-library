# 三个模型制作任务单

> 目标：产出 3 个「能看」的模型，分别用 Blender / Maya / 3ds Max 制作，
> 走完整优化流水线后上传 COS，在小程序里可预览。
>
> 这份文档同时是**简历材料的核心**：它证明了「跨 DCC 交付能力」。

---

## 一、分工

| # | 软件 | 模型 | 难度 | 为什么选它 |
|---|---|---|---|---|
| 1 | **Blender 5.2** | 台灯 | ★★ | 硬表面 + 圆柱体，拓扑好控制，最能练基本功 |
| 2 | **Maya 2022** | 陶瓷杯 / 花瓶 | ★★ | 旋转体，重点练 UV 展开 |
| 3 | **3ds Max** | 木箱 / 书架 | ★★★ | 硬表面切角，最能暴露单位与轴向问题 |

> 三个都不要「雕花」级别的细节。目标是**干净、规范、能优化**，不是炫技。

## 二、通用验收标准（三个模型都必须满足）

| 项目 | 标准 | 为什么 |
|---|---|---|
| **面数** | 单个 ≤ 3000 三角面 | 移动端预算，超了必卡 |
| **拓扑** | 以四边面为主，无明显 n-gon | 减面时不会烂 |
| **UV** | 必须展开，无重叠，留 2px 边距 | 贴图不串色 |
| **材质** | PBR：baseColor / metallic / roughness | glTF 标准通道 |
| **贴图** | ≤ 1024×1024，PNG 或 JPG | 移动端显存 |
| **变换** | 应用所有变换（scale 归 1、rotation 归 0） | 导出不跑偏 |
| **原点** | 放在物体底部中心，Y=0 贴地 | 统一摆放基准 |
| **命名** | 英文、无空格，如 `lamp_body` | 跨软件不乱码 |
| **单位** | 模型高度按「米」估算，台灯约 0.5m | 三端统一 |

## 三、各软件导出设置

### 3.1 Blender → GLB（直接导出）

菜单：`File > Export > glTF 2.0 (.glb/.gltf)`

| 设置项 | 值 |
|---|---|
| Format | **glTF Binary (.glb)** |
| Include | 勾 Selected Objects（只导选中的） |
| Transform → **+Y Up** | ✅ 必须勾（Blender 是 Z 轴向上，glTF 是 Y 轴向上） |
| Data → Apply Modifiers | ✅ 勾（把修改器烘焙掉） |
| Data → Normals | ✅ 勾 |
| Data → Tangents | ✅ 勾（有法线贴图时必须） |
| Material → Images | **Automatic**（贴图打包进 glb） |

### 3.2 Maya → FBX → GLB（两步）

Maya 2022 **没有内置 glTF 导出**，标准做法是导出 FBX 再转换：

**第一步：Maya 导出 FBX**
`File > Export Selection` → 文件类型选 **FBX export**

| 设置项 | 值 |
|---|---|
| Up Axis | **Y**（Maya 默认 Y-up，保持） |
| Units | centimeter / 或与场景一致 |
| Smoothing Groups | ✅ 勾 |
| Embed Media | ✅ 勾（贴图打包） |
| Triangulate | ❌ 不勾（保留四边面，后面再减面） |

**第二步：FBX → GLB 转换**
用 `FBX2glTF` 命令行（开源工具），或丢进 Blender 中转一次。
转换脚本我们后面放到 `tools/` 里，一条命令搞定。

### 3.3 3ds Max → FBX → GLB（两步）

`File > Export` → 文件类型 **FBX**

| 设置项 | 值 |
|---|---|
| Up Axis | **Y**（⚠️ Max 默认是 Z-up，这里必须改成 Y） |
| Units | **Meters**（⚠️ Max 默认是英寸/通用单位，必须改） |
| Embed Media | ✅ 勾 |
| Preserve edge orientation | ✅ 勾 |

然后同样走 FBX → GLB 转换。

## 四、跨 DCC 差异表（这就是简历上要讲的东西）

| 差异点 | Blender | Maya | 3ds Max | 统一方案 |
|---|---|---|---|---|
| **向上轴** | Z-up | Y-up | Z-up | 导出时统一成 **Y-up** |
| **默认单位** | 米 | 厘米 | 通用单位 | 导出前统一成**米** |
| **旋转顺序** | XYZ | XYZ | ZYX(默认) | 应用所有变换后再导 |
| **平滑组** | 用 Shade Smooth | 平滑网格 | Smoothing Groups | 导出前全部应用 |
| **贴图路径** | 相对/打包 | 工程目录 | 材质编辑器 | 一律**打包内嵌** |
| **法线** | 需手动反转时常见 | 一般正常 | 翻转面常见 | 导出后**必检查法线** |

**面试话术**：
> "三个软件导出的模型直接进引擎，会出现朝向不对、大小差 100 倍、法线翻转三类问题。
> 我做了一套导出预检清单，把轴向、单位、法线、UV 四项在导出前统一，再进优化流水线。"

## 五、每个模型完成后要跑的三步

```bash
# 1. 优化（减面 / 去重 / 贴图降采样 / Draco）
把 xxx.glb 拖到 tools\optimize.bat 上

# 2. 检查体积与面数
cd tools
npx @gltf-transform/cli inspect xxx.opt.glb

# 3. 上传 COS，更新 models.json
```

**记录每个模型的「优化前 → 优化后」体积**，这是简历上的数字来源。

## 七、常见坑

| 坑 | 表现 | 解决 |
|---|---|---|
| 导入后模型巨大/极小 | 单位不一致 | 导出前统一成米 |
| 模型躺倒 | 轴向没转 | 导出勾 Y-up |
| 模型全黑 | 法线翻转 | 在建模软件里 Recalculate Normals |
| 贴图丢失 | 没打包 | 导出时勾 Embed Media |
| 减面后破面 | 拓扑是三角面/ngon | 建模阶段保持四边面 |
| 手机加载很慢 | 贴图 4K | 降到 1024 或 512 |
